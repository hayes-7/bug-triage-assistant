### v1.1 — 严重度判定标准

**变更动机**：

`baseline` 批次（280 条，`data/eval_metrics_baseline-20260920.json`）实测显示，严重度是全指标中与目标差距最大的一项：严重度准确率 **28.57%**，距目标 65% 差 36.4pp；同期分类 Top-1 已达 **70.36%**（目标 55%），已超目标。按「资源投在差距最大处」的原则，v1.1 由 PD-07 原定的「类别定义」改为「严重度定义」，类别定义推迟至 v1.2。

混淆矩阵（`severityConfusionMatrix`，外层为预测、内层为标准答案）给出的具体错误模式：

1. `low` 档 **158** 个标准答案**零预测**（perSeverityF1 · low = 0.0000）。根因判定：PD-02 中 `low` 的定义为「无上述标签」，属**否定性定义**，无正面判别特征，模型无法据此建立边界；
2. `normal` 档标准答案仅 **8** 个，却被预测 **134** 次，占全部预测近半，属严重过度预测；
3. `high` 档召回仅 **35/72**，按字面理解为「重要」而非「版本回归」，与 PD-07 第 4.2 节的预判一致；同时 `crash` 档 F1 已达 0.8989，说明崩溃类信号本身无需额外说明。

因此本版只做两件事：为四档各自补一条正面判定标准（`low` 尤其要从排除式改为正面描述），并在 `high` 档显式点出 `"worked in 4.1"` / `"Not reproducible in <older version>"` 这类版本回归强信号。

**具体变更**：

仅改 `SYSTEM_PROMPT` 的第 2 段（Severity）：在 `crash, high, normal, low` 之下新增 `Definitions:` 四档说明，其余段落（模块类别、信息充分度）、`buildUserPrompt`、`MODEL_PARAMS`（temperature 0 / maxOutputTokens 800）、`INPUT_TRUNCATE_TOKENS`（1500）与 v1.0 **逐字一致**。

刻意未做（保证 v1.1 与 v1.0 的差值可独立归因于「明确严重度判定标准」这一手段）：
- 不补充类别判定说明（v1.2）；
- 不补充信息充分度判定标准（v1.3）；
- 不加入 few-shot 示例；
- 不注入任何检索内容。

| perSeverityF1 · low | 0.0000 | > 0.30 | **0.0000**（未达标，仍零预测） |
| 预测为 normal 的次数 | 134 | < 80 | **78**（达标） |

**预期取值理由**：

- **严重度准确率 45%–55%**：`low` 从零预测转为可预测，且 `normal` 过度预测被压缩，两项合计即可带来约 20pp 量级的提升；未给到 65% 目标值，是因为 `high` 档在真实数据中与 `low` 的边界仍依赖撰写者是否写明旧版本行为，提示词无法凭空补齐该证据。
- **low F1 > 0.30**：正面定义可让模型建立边界，但 `low` 真值占比 56%（158/280），保守起见只要求 F1 过 0.30，不预期一次到 0.6 以上。
- **预测 normal < 80**：`normal` 真值仅 8 条，134 次预测中绝大多数应被 `low` / `high` 吸收；即便只吸收一半，也应降至 80 以下。
- **high 召回 > 45/72**：显式点出版本回归句式后，原本被判为 `normal` 的 34 条（混淆矩阵中预测 high / 真值 normal 为 34）会回流；保守估计新增 10 条以上。
- **分类 Top-1 / Top-3 基本不变**：本版未触碰任何类别相关表述，若出现超过 ±2pp 的变动，须先排查是否误改了模块段或混入了其他变更，不得直接归因于严重度定义。

**证伪条件**（若出现，须在「实际结果与判断」中记录原因，不得直接回退并忽略，依 PD-05 第 9.3 节）：

1. 严重度准确率提升不足 10pp → `low` 的正面定义仍不足以建立判别边界，须考虑改用示例（v1.2 起）而非继续加长描述；
2. `low` 召回上升但 `normal` 预测数未下降 → 说明模型是在 `normal` 与 `low` 之间整体平移，而非真正学会区分，须重新审视两档定义的互斥性；
3. 分类 Top-1 变动超过 ±2pp → 本版改动超出严重度范围，须逐行 diff v1.0 与 v1.1 的 SYSTEM_PROMPT 确认。

**few-shot 示例来源**：本版未增删示例，`prompts/triage_v1_1.ts` 中登记为「示例样本编号：（无）」。

**实际结果与判断**（`sev-defined` 批次，2026-09-21 执行）：

**批次执行状况**：280 条主集 + 20 条对抗集，共 300 次端到端调用，失败 0、降级 0、重试率 0、首次解析成功率 100%，耗时 23.9 分钟；dev server 全程未中断（baseline 批次曾因中断致 Top-1 虚高约 5.34pp，本批无此问题）。查重段未执行：运行环境缺 `psycopg2`，脚本自动跳过；该段属检索路径、与 Prompt 版本无关，不影响本版结论。

**预期核对**：6 项中 3 项达标（预测 normal 78 < 80、high 召回 61/72 > 45/72、Top-3 90.0% 不变），3 项未达（severityAccuracy 37.50% 未入 45–55% 区间、low F1 仍为 0.0000、Top-1 +2.86pp 超 ±2pp）。

**命中证伪条件 1**（严重度准确率提升不足 10pp，实测 +8.93pp）——原因记录如下：

1. `low` 仍为零预测：158 条真值 low 全数落入 high 84 / normal 65 / crash 9，预测 low 为 0/280，F1 保持 0.0000。
2. `high` 过度预测并非由「版本回归句式」直接触发：被判 high 的 84 条真值 low 中，仅 12 条（14.3%）含显式回归表述（`worked in` / `not reproducible in` / `used to work` 等），低于全样本基准率 20.7%；示例 #100730、#83193、#70722、#84431 均为「某功能行为不符合预期」的普通报告，正文带 `### Godot version` / `Tested versions` 头但无新旧版本对比。判读：模型把「功能与预期不符」整体映射为 high。
3. `low` 定义仍缺唯一锚点：本版给 low 的「localized or edge-case defect that does not block the main workflow」以程度修饰与否定条件为主，与 normal / high 的语义域重叠，模型在任何情形下都不会优先选它——与 v1.0「无上述标签」属同一类失效，只是换了措辞。
4. 代价：high 预测数 99 → 151（其中 90 条误报），crash F1 由 0.8989 降至 0.8172（9 条真值 low 被吸入 crash）。严重度准确率的 +8.93pp 中相当部分被自身引入的 high 过度预测抵消。

**命中证伪条件 3**（Top-1 变动超 ±2pp）——已按要求逐行 diff v1.0 / v1.1：模块段、信息充分度段、`buildUserPrompt`、`MODEL_PARAMS` 均与 v1.0 逐字一致，`SYSTEM_PROMPT` 唯一差异为 Severity 段新增 Definitions，故「改动超出严重度范围」不成立。+2.86pp（197/280 → 205/280，+8 条）判为严重度定义对模型整体解读的间接影响叠加温度 0 下的残余波动，不对分类指标下结论。另注：baseline 的 70.36% 本身可能因中途中断而失真，该对比基准须以重跑的干净 baseline 复核。

证伪条件 2 未命中（low 召回未上升，且 normal 预测数由 134 降至 78）。

**处置**：不回退、不修改 v1.1，实测值原样保留。下一步（不属本版）：v1.2 起为 `low` 建立唯一正面锚点（纯外观 / 文案 / 极端配置等），并为 `high` 增加「须存在新旧版本对比证据，否则不适用」的显式约束。

### v1.2 — 严重度判定程序化

**变更动机**：

`sev-defined` 批次（280 条主集，`data/eval_metrics_sev-defined.json`）实测，v1.1 的四档并列定义失效，且失效方式具有机制性：

1. 严重度准确率 **37.50%**，未入预期区间 45–55%，命中 v1.1 登记的证伪条件①（提升不足 10pp，实测 +8.93pp）；
2. `low` 档 158 个标准答案**仍为零预测**（0/280，perSeverityF1 · low = 0.0000）。v1.1 已把 `low` 从否定式改为正面形容词描述（localized / edge-case / minor），仍无效——说明问题不在措辞，而在范式；
3. **模型跑不赢"全猜 low"**：朴素基线 = 158/280 = **56.4%**，高于模型实测 37.50%。模型与多数类反向，是判定机制失效的直接证据；
4. 吸引子随"默认感"转移：v1.0 无定义→`normal`（字面义）吸走 134 次；v1.1 定义篇幅最长的是 `high`→`high` 成新吸引子（预测 151 次，其中 84 条真值 `low`，精确率 0.404）。**只要继续走"四档定义并列竞争"范式，篇幅最长者必成吸引子**。

由此得到三个机制级判断：

- `low` 是**程序性/残余类别**（占 56%），本质是"排除其他档后的默认桶"。它不可被"识别"，只能被"排除后到达"；任何形容词式正面定义描绘的形象都远窄于真实外延，与 v1.0「无上述标签」属同类失效，只是换了措辞。
- 要改变吸引子，只能改变**程序位置**，不能改变**篇幅**。故本版把严重度写成按序执行的判定程序，并刻意让 `low` 的措辞短于 `high`。
- `high` 的过度预测源于"功能与预期不符 → 重要 → high"的语义漂移（84 条误报中仅 12 条，14.3%，含显式回归表述，低于全样本基准率 20.7%）。故对 `high` 增设**证据门槛**：无版本对比证据即不适用。

**具体变更**：

仅改 `SYSTEM_PROMPT` 的第 2 段（Severity）：由 `crash, high, normal, low` + `Definitions:` 四档并列说明，改为 `determine in this order` 的 (a)→(b)→(c)→(d) 判定程序：

- (a) crash — 异常终止/挂起/不可用，信号为 stack trace、segfault、freeze；
- (b) high — **REGRESSION**，须存在版本对比证据（`"worked in 4.1"` / `"Not reproducible in <older version>"` / `"used to work before"`），**无证据则本档不适用，即便缺陷看似重要**；
- (c) normal — 功能仍可用但退化：明显性能损失或不阻断工作流的可用性问题；
- (d) low — **其余全部**，且明确声明为 MOST COMMON 档（约占一半），并规定 **none of (a)-(c) clearly matches 时 MUST choose low**。

其余段落（模块类别、信息充分度、信号取值清单）、`buildUserPrompt`、`MODEL_PARAMS`（temperature 0 / maxOutputTokens 800）、`INPUT_TRUNCATE_TOKENS`（1500）与 v1.1 **逐字一致**；`PROMPT_VERSION = "v1.2"`，`EVAL_BATCH_LABEL = "sev-procedural"`。

刻意未做（保证 v1.2 与 v1.1 的差值可独立归因于「判定程序化」这一手段）：
- 不补充类别判定说明（继续推迟）；
- 不补充信息充分度判定标准（继续推迟）；
- 不加入 few-shot 示例（v1.3）；
- 不注入任何检索内容（v2.0）。

**预期取值理由**：

### v1.3 — few-shot 示例

**变更动机**：

`sev-procedural` 批次（280 条主集，`data/eval_metrics_sev-procedural.json`）实测，v1.2 的判定程序只生效了一半，且失效点明确：

2. (a) crash 前置生效（crash 召回 38/42 → 42/42），但 (d) `low` 作为程序**终点未被执行**：预测 `low` 仅 13 次（召回 6/158），模型在 (c) 就停下；
3. 吸引子由 (b) high 转移到 (c) normal：预测 `normal` 由 78 升至 **126**，其中 **109 条真值 `low`**，几乎回到 v1.0 的 normal 吸引子形态（134 次）；

机制判断（决定本版路线）：v1.2 证明**模型不执行程序，只做语义最近邻匹配**。顺序指令与 MUST 是软约束，改不了最近邻的结果；而 few-shot 是三版里唯一与该机制不冲突的路线——它不给规则，给锚点。同时，示例的**数量分布**是模型能直接感受到的硬信号，故按「low 是多数类（真值占比 56%）」把 low 示例配比拉到 6/12（补丁 1），破「回避 low」倾向。

**具体变更**：

仅改 `SYSTEM_PROMPT` 的第 2 段（Severity）：在 (a)-(d) 判定程序**之后**、`Also indicate which signals...` **之前**，新增 `Worked examples (match by meaning; these are anchors, not rules to copy verbatim)` 段，含 12 条自然语言叙述示例（引号包裹的报告标题 + 档位 + 一句理由）。
